# APEX early launch

Lead with one concrete story: **two developers, their own agents, one shared project chat and a vault that remembers the decisions.** Provider count and feature lists support that story; they are not the opening pitch.

## First users

1. Recruit 5-10 developers who already work with another person on a small repository. Watch a fresh install and their first shared task. Ask where setup, permissions, context or source synchronization got confusing.
2. Record a 60-90 second demonstration: install, open the project, two people chat, `@apex` handles one task, switch to a personal tab and inspect the saved vault. Use a real task; identify any fixtures or edited footage.
3. Make one 4-6 minute walkthrough showing provider setup, permissions, costs, an actual edit/check and how the second person joins. Give the prerequisites and known Windows/remote-hub limits.
4. Share the short demonstration with an invitation to try one workflow and report one problem. Use communities that permit relevant self-promotion and answer technical questions yourself.
5. After the install and first-session problems are addressed, consider a Show HN post linking to the working public repository and a straightforward way to try it. The official guidelines favor something people can use, not a teaser.

## GitHub as the destination

Keep the install command, current CI result, screenshots, documentation and known limitations obvious. Use relevant repository topics, tagged release notes and reproducible issue reports. Label small, well-scoped contribution opportunities only after real issues exist. Do not manufacture issues, stars, reviews or testimonials.

Measure successful installation, completion of a first shared task and return use after a week. Stars and download counts are useful signals, but are not proof that developers found the tool valuable.

## Spending and claims

Start with documentation, demonstrations and direct feedback. Do not buy ads before people can reliably reach the core workflow. Do not advertise better coding accuracy than other agents without representative evidence, claim unlimited free API use, or imply fully managed cross-machine synchronization.

Sponsorship links and centrally funded model usage remain disabled. Nothing in this plan authorizes paid promotion or posting to other people's channels.

References: [Show HN guidelines](https://news.ycombinator.com/showhn.html), [GitHub repository topics](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/classifying-your-repository-with-topics).
